Separate evidence.

The public baseline and the accepted barrier deletion passed numerical testing on B200. The rejected deletion exposed a real race. The measured candidate offers no demonstrated speedup.

Three different questions

SentryWard checks synchronization under the fixed contract. CPU-reference comparisons test sampled numerical outputs. CUDA-event measurements report execution time. None substitutes for the others.

Each numerical run uses 39 cases, repeated three times. Positive variants matched every BF16 reference output exactly in these samples; maximum relative norm error was 7.26e-08. The predeclared limits were 1 BF16 ULP, and float norm tolerance 2e−6 relative + 1e−7 absolute.

The rejected candidate failed 4 cases in run 1 but passed the numerical samples in run 2. Racecheck found a shared-memory hazard in both runs. Passing samples do not establish race freedom.

All three variants had zero memcheck findings in the instrumented smoke case. This does not approve the rejected variant.

The selected change removes the barrier at original PTX line 167, on a branch skipped by the fixed 256-thread launch. Static barrier count drops from 16 to 15; executed work is not reduced. One shape and one B200 were benchmarked; clocks were not locked on this shared server.
